## 响应式与 200% 文字的核查范围

用实际 CSS 尺寸和本项目 Inter WOFF 字体的横向字宽做静态计算，没有启动浏览器，也没有把计算值写成截图测量结果。字宽计算不包含浏览器 shaping/kerning，因此只能用于发现约束冲突和安排复测。

| 宽度（CSS px） | 当前布局路径 | 推算图表内容宽度 | 应重点复测 |
| --- | --- | ---: | --- |
| 320 | 三项导航；剂量双列，日期/时间整行；设置单列 | 266 px | 导航与三天日期标题换行、原生日期输入、登录和药品弹窗、表格横向滚动；图表当前最小 viewBox 280 会轻微缩小实际字体。 |
| 375 | 同上；分类强度选择另起一行 | 321 px | 长药名、强度单位、库存小数、三天标题；注意此宽度命中 380 断点。 |
| 390 | 剂量日期/时间并排；设置单列 | 328 px | 12 小时时间控件、±5/10 min、复方长名称、弹窗保存入口。 |
| 768 | 剂量采用中间宽度的多行网格；设置单列 | 670 px | 键盘和触屏双输入、表单焦点、错误出现后滚动位置。 |

本轮确认的文字放大约束是：导航不换行、三天标题 `overflow:hidden`、输入固定高度。以 320 px 为例，首个导航项内容分配约 98 px，而其 200% Inter 文本横向字宽约 201 px；固定单行必然超出本栏。三天日期栏约 67 px，200% 的 `Wed, Sep 30` 约 135 px。这里的 **200% 仅文字缩放** 与浏览器整页缩放不同，不应混写。

已先告知主执行者后修正 CSS：导航和日期标题允许换行；常规输入/选择框高度随文字增长，同时保留 42/44 px 最小高度。PostCSS 解析通过。**是否出现原生输入裁切、SVG 刻度重叠或横向页面滚动，仍必须在真实浏览器复核。** 特别是 72 小时图表的 SVG 小字不会因普通 HTML 换行规则自动避让，不能将 CSS 修复当作这部分已验收。

未发现需要另加鼠标专属拖拽键盘实现的证据：图中计划剂量虽以指针拖动，但同一数据已有可聚焦的日期/时间输入及 earlier/later 按钮。实际记录不能拖动，另有明确 Edit。原生 dialog 使用 `showModal()`、`cancel` 和 `close()`，具备原生模态基础；仍需实测焦点进入、Esc 和关闭后的焦点恢复。

### 后续更新：手机小时/分钟滚轮

新增独立 MobileTimePicker 与专用 CSS：常态是 44 px 高的单行时间按钮；native dialog 作为底部面板，包含小时、分钟两个滚轮，常规高度显示五个选项，短屏显示三个。小时实际有 24 个值，12 小时制逐项显示 AM/PM；5/10 分钟选择中会临时保留原值的非步长分钟，如 08:03 或 23:59。改变滚轮只更新面板草稿，Done 才提交，Cancel/Esc 不提交，Now 只调用父组件的当前时刻操作。

实现参考 [WAI Listbox 键盘与语义](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)、[CSS scroll-snap-type](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scroll-snap-type) 与 [scrollend 事件边界](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollend_event)。每个滚轮只有一个 Tab 停靠点，提供选项与 active-descendant；方向键、Page Up/Down、Home/End 可选值，左右键切列。Done 直接读取当前 DOM 中距滚轮中心最近的行，停止滚动后提交该值，不依赖可能延迟的 React state 或 scrollend 事件。

4 项持久化 helper/SSR 测试通过。另有 7 项实际转译组件加合成 DOM 几何的检查通过：原 08:03 打开/Done 不变；点新小时后 Cancel 不提交；Esc 不提交；Now 只调用 onNow 并关闭；未派发 scroll 事件时 Done 仍从滚动位置得到 10:10；键盘 End/PageUp/左右切轮得到正确值；10 分钟偏好仍保留 23:59。TypeScript 与专用 CSS 解析通过。该组几何是受控对象，**不是 iPhone 触摸惯性或浏览器布局实测**；原生面板、滚动手感、软键盘与 VoiceOver 仍由主执行者在可用浏览器验证。

## 双击启动器：实际执行了什么

仅从启动脚本（测试时名为 **Start Dose Timeline.command**，现更名 **Start Drug Tracker.command**）提取内嵌 Node 健康检测程序执行，测试服务器使用操作系统分配的临时 **127.0.0.1** 端口、合成响应。没有执行整份启动脚本，没有启动应用服务，没有打开浏览器，也没有接触正式数据库。首次默认沙箱不允许监听临时端口；经工具批准后执行同一隔离测试，全部通过。

| 合成场景 | 实际退出码 | 结果 |
| --- | ---: | --- |
| `ok:true`、`storage:local-sqlite`、`schemaVersion:2`，JSON、HTTP 200 | 0 | 识别为本应用健康接口 |
| 其他 JSON 服务 | 2 | 不复用 |
| HTML 服务 | 2 | 不复用 |
| 不支持的 schemaVersion | 2 | 不复用 |
| `ok:false` | 2 | 不复用 |
| HTTP 500 | 2 | 不复用 |
| HTTP 重定向 | 2 | 不跟随；请求计数验证没有访问跳转目的地 |
| JSON 无法解析 | 2 | 不复用 |
| 连接后不响应 | 2 | 超时退出，单项测试在 4 秒内完成 |
| 没有监听服务 | 1 | 判断为可尝试启动 |

检测器的 TCP 端口原先重复写死 4310，已改为读取同一传入 URL 的端口，避免检测与 URL 不一致，也使上述临时端口测试可行；双击脚本仍固定 `PORT=4310`。`zsh -n` 与内嵌 JavaScript 语法检查通过。

静态核对还包括：PATH 中 Node 必须 ≥24，否则使用明确的本机备用路径；脚本先切换到自身目录；只使用已有 dist 与 node_modules；不自动安装或构建；正式数据库路径固定；只结束自己启动的子进程；已有健康服务只打开页面。终端信号、Finder 双击、首次启动、浏览器自动打开以及长时间保持服务，**尚未由本轮测试执行**，需单独做启动流程验收。
