# Reference expansion: bounded privacy and security crosscheck

Reviewed 2026-09-14, independently from the other change reviewer. This was a read-only application-code review with existing synthetic tests; the only edits were documentation. It is a second check within the AI workflow, not an independent professional audit or evidence that a particular build has been deployed. No blocking issue was identified within this scope.

## Checked behavior

- **Static references:** inspected the MPH, common MPH, amphetamine, common stimulant, nonstimulant and Azstarys reference/source modules. They contain bundled numeric data, text and fixed official-source URLs. No fetch, beacon, socket, browser-storage access or runtime external source download was added by these modules. Source links carry no dose/account query data. Clicking a link deliberately contacts the external site; chart links use `rel="noreferrer"`, and cloud responses set `Referrer-Policy: no-referrer`. This is not a claim that hosting infrastructure produces no connection metadata.
- **Switching and record identity:** `timelineChoices` builds view-owned arrays without modifying doses. Medication and analyte selectors update local React selection state; they do not invoke a save, delete, authentication or transfer API. Samples and record references belong to the chart view rather than a global health-data cache. The shared absorption-rate cache is keyed by public reference channels and stores only numeric rates. Actual-record markers cannot use the optional simulated/planned drag callback. Existing tests check unchanged input snapshots, separate formulations, earlier same-formulation doses, and one displayed chart/reading.
- **Static chart guide:** `chart-guide.html` is explicitly included in `server/cloud.mjs`'s startup build snapshot and documentation-page allowlist. Requests serve the captured bytes, not a caller-selected filesystem path. Its CSP is `default-src 'none'` and `script-src 'none'`, with inline styles permitted; form submission and framing are disabled. The actual guide contains no scripts, forms, trackers or remote font loads. GET/HEAD retain `no-store`; other arbitrary HTML files, traversal and symlink substitutions remain blocked by the existing static-serving boundary. The startup directory must still be trusted, as documented in the server.
- **Check username:** the control reads only `user.username` from the authenticated account passed by App, not the editable health profile/display name or an arbitrary username lookup. Opening it adds no network request and asks for no password. A missing username is shown as unavailable. App keys Settings by account ID; account data loading checks generation/owner, and CloudGate clears the account workspace when a session check reports another owner or a protected request returns 401. The username display therefore does not create a public account-enumeration endpoint or expose another account's profile. As with the existing account view, peer revocation is detected on the next session/protected request rather than instantaneously on every device.

## Verification and limits

Node 24 existing tests: **11 passed, 0 failed, 0 skipped** across `timeline-choice.test.ts`, `cloud-public-assets.test.mjs`, and `cloud-security-username.test.mjs`. The HTTP tests use temporary synthetic databases and a loopback port; they do not read the personal or production database. The sandbox initially blocked loopback binding with `EPERM`; the same bounded tests then passed with approved local-server execution. No code change was made in response to that environment restriction.

This check did not repeat the previous cryptographic/authentication audit, inspect production traffic or provider logging, establish clinical validity of the reference curves, or verify deployment/provenance. Existing same-origin JavaScript/device trust boundaries and hosting metadata disclosures still apply. A reference source being public or a page having a CSP does not make the whole application risk-free.
