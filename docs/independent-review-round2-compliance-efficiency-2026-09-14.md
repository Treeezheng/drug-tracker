# Independent review, round 2: privacy copy, medical presentation, release materials and efficiency

Date: 14 September 2026. Reviewer: a separate OpenAI Codex agent in the second review round.

This review started from application source and public-facing documentation on `codex/independent-security-review`, based on main `f6c01e75`, with the pending fixes present. Previous audit reports and their conclusions were not used to form the initial findings. The changed implementation was examined after that source review. This is an AI-assisted engineering review, not a professional independent audit, clinical validation, legal opinion or compliance certification.

## Findings and disposition

### P2 — History repeatedly converted every record for every chart period

The previous History implementation built each bar by filtering all selected medication records, converting each administration into the report time zone inside that filter. The work repeated on every render. A synthetic 1,000-record history across 60 months took **3,475 ms** for this bucketing loop alone on this review machine. This is an ordinary multi-year history, well below the accepted import size. Blocking the browser's main thread for this work makes record inspection and filter changes unresponsive.

Fixed in [`history-bars.ts`](../src/lib/history-bars.ts) and the History component in [`App.tsx`](../src/App.tsx). Each administration date is now converted once and added to a calendar-period bucket. Amounts remain exact decimal strings; floating-point conversion is confined to drawing bar height and the chart scale. The History component memoizes range filtering, medication selection, ingredient lists, summaries and chart construction against their actual inputs. The parent reviewer additionally identified that the summary rescanned records for every product even though only one selected product's summary was rendered. The final implementation summarizes only the selected rows and aggregates their ingredient totals in one pass.

The same synthetic 1,000-record/60-month case took **73 ms** in a separate measurement of the new helper. Both old and new measurements assigned 999 records to the selected range because the first UTC midnight fell on the previous local date in Los Angeles. These are local kernel measurements, not browser-frame timings or a general performance guarantee. A regression test checks the substantive complexity invariant: the administration-time property is read once for each of 1,000 records, instead of once per record per month.

### P3 — Long selected ranges silently omitted their final chart periods

The old monthly loop stopped after 1,200 months. An accepted custom range of **1900-01-01 through 2026-09-14** produced bars only through **1999-12**, while the chart described the full selected range. Recent records remained in totals and the table but disappeared from the chart without an explanation.

Fixed by widening calendar periods without dropping either end of the range. Up to 62 days use daily bars; longer ranges use monthly bars while that fits within 1,200 bars, then yearly or explicitly labeled multi-year periods. The example above now shows 127 yearly bars including 2026. A test spanning the full accepted years 0001–9998 confirms that both endpoints are included, the bar count stays bounded, and exact totals are preserved. The heading and accessible chart description disclose the actual aggregation. Partial first and last periods contain only records within the selected dates.

No additional verified high or medium finding was identified within this review's scope after these changes. That statement is limited to the reviewed code and evidence below.

## Coverage and conclusions

**Privacy and service copy.** Reviewed `PRIVACY.md`, `TERMS.md`, `SECURITY.md`, `README.md`, the public privacy and terms HTML, account/settings disclosures, guest-consent/session storage behavior, report downloads and backup validation. A local text comparison found every substantive Markdown policy paragraph in its public HTML counterpart: 44 privacy paragraphs and 29 terms paragraphs, with no unmatched paragraph. This comparison normalizes formatting and link markup; it does not validate a deployed page.

The reviewed disclosures distinguish remembered guest plaintext, local-edition plaintext storage and cloud browser encryption. They identify server-readable account/session/connection metadata, Heroku infrastructure reporting, plaintext exports and recovery downloads, unsaved-memory loss, provider-retention uncertainty and the fact that old copied ciphertext cannot be revoked. The age acknowledgment is described as self-confirmation, not identity verification. The terms do not present the application as clinically validated or legally certified. This review found no undisclosed analytics, advertising or remote-font integration in the inspected application paths. It did not inspect provider accounts, production logs, retention settings or third parties' independent processing.

The parent task is handling terminology consistency between the current **Hide** control and older **Lock** documentation, and deployment documentation for the new explicit proxy mode. No statute-specific applicability determination is made here. Operator identity, geographic applicability, actual provider practices, rights-request handling, material-policy notices and incident-response execution require facts and actions beyond source inspection; policy text does not establish that those obligations have been satisfied.

**Medical and record meaning.** Reviewed `model.ts`, `model-formula.ts`, `timeline-data.ts`, `timeline-scope.ts`, `timeline-estimates.ts`, `timeline-series.ts`, `TimelineChart.tsx`, History and symptom presentation, the medical disclaimer, and CSV/backup code. Direct modeled values remain distinct from proportionally scaled, starred reference estimates. Unknown contributions do not become personal measured concentrations or evidence that medication has cleared. Compatible analytes and relative-unit illustrations remain separate; saved assumptions are described as unvalidated. Concerta's observed boundary and estimated continuation are disclosed; the Ritalin equation and constants agree with the implemented function. This checks implementation meaning, not the independent validity or digitization of medical source data.

Reports exclude planned/simulated administrations, resolve latest revisions before range filtering, preserve exact recorded quantities, separate ingredient snapshots from unknown legacy ingredient amounts and label nominal patch delivery. CSV output quotes cells and neutralizes formula prefixes; exports remain expressly unencrypted. Symptom comparisons describe same-day observations and avoid claims of causation or proof that an unrecorded dose did not occur. Backup parsing validates bounded size and structure and rejects unsafe object keys. Server-side import/authentication authorization was assigned to the other reviewers.

**Chart sampling and memoization.** The new chart sampling helper shares evaluated contributions between totals and individual paths, stores only required plotting metadata per sample, and keeps its cache owned by the mounted view. There is no new module-global plaintext-record cache. Sample times, record sets, time-zone interval, published-only mode and geometry width are represented in the relevant dependencies. Pointer readings are evaluated at the selected time, while resize work can reuse numeric samples. Focused tests cover scaled/direct estimates, unavailable data, future zeros, separate relative units, observed/estimated transitions and null gaps. The bounded sample count does not itself bound the number of retained records or guarantee smooth interaction for every account size.

**Dependencies, licenses and release materials.** Reviewed `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, the notice generator and its tests, CI and Dependabot configuration, Heroku/build-metadata scripts, deployment templates/guides and the source-data ignore rules. CI uses frozen dependencies, pinned action commits, read-only default repository permissions, a disposable PostgreSQL service, edition checks, repeat-build comparison and a separate main-only attestation job. The manifest's environment serialization is an explicit public allowlist. These mechanisms do not prove which build is live or prevent future malicious website code; the project documentation acknowledges those limits.

The notice checker passed against this installation: **56 packages, 83 notice sections and 22 embedded source headers**. The complete same-platform check and portable check both passed without rewriting notices. Independent inspection of the lockfile found the current Darwin/Linux differences in explicitly OS/CPU-constrained native optional packages, including esbuild, rolldown, lightningcss and fsevents; their relevant platform snapshots do not introduce an unrestricted transitive dependency that would need a platform exception. The portable tests reject stale shared legal text, changed lock hashes, mismatched summaries/counts and missing unrestricted optional packages. An additional temporary pnpm-style symlink fixture independently verified reachable dependency/peer resolution and exclusion of stale store entries.

The portable check intentionally does not re-audit the legal text of native packages absent on the running platform. Its explicit OS/CPU rules are suitable for the current Darwin-to-Linux CI comparison; they are not a general promise of compatibility between arbitrary libc variants or future package graphs. An actual Ubuntu frozen installation and CI run remain release verification, not something this macOS review simulated or claimed. Supplied upstream notices are preserved; the generator is not an independent legal audit of every embedded upstream component. The parent task's dependency advisory scan is separate evidence and does not rule out unknown vulnerabilities.

## Remaining limits

History still renders all selected record rows, and symptom views can render all selected check-ins. Filtering, export preparation and the first rendering of a very large permitted account therefore remain proportional to its data, and many thousands of DOM rows can be expensive. The new bucketing work removes repeated period-by-record conversion; it does not establish 50,000-row mobile responsiveness or replace pagination/virtualization. Large timeline record sets also require initial model evaluation despite memoization. No performance claim is made for every browser or physical device.

The parent task must complete whole-suite/build checks, any integrated browser checks, actual Linux CI, review of the exact source commit and final deployment/asset verification. This report is evidence of this review's coverage and fixes, not a statement that the eventual release is completely secure, medically valid or legally compliant.
