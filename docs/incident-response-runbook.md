# Drug Tracker：隐私与安全事件响应

核对日期：2026-09-13。负责人：**Treee**；私密报告渠道：**uhenrywksp@icloud.com**。这是发生事件时应执行的流程，**不表示已经配置全天值守、自动告警、定期日志巡检或备份恢复演练**。不得把邮件地址当急救渠道；不得要求报告者发送密码、恢复密钥或完整健康导出。

## 发现与限制影响

1. 接到可信报告或发现异常后，记录最早发现/通知时间及 UTC 时区、发现者、受影响版本/域名、已知事实和待核实事项。为法律时钟保留“应当合理发现”的时间线，不能等调查完成才开始计时。
2. 保存必要证据到受限位置：部署 commit/build、时间戳、脱敏响应头、平台事件和必要日志片段。不要公开健康资料、原始 cookie、数据库凭证、带签名的备份 URL 或恢复密钥。不要为取证把生产库导入 GitHub、第三方 AI 或公开 issue。
3. 按实际证据限制入口：例如暂停提供受损脚本、暂停注册/写入、撤销会话、替换泄露的部署/数据库凭证。先保全必要证据，再变更系统，记录每次操作。会话撤销不能远程抹除已经解锁的浏览器或下载文件。
4. 如果 delivered JavaScript 或客户端设备受损，评估单一主密码、完整恢复码、浏览器 export key、数据密钥和当时解锁的数据均可能泄露。服务器数据库受损时，逐项判断 OPAQUE setup secret、注册记录、恢复认证 hash、未过期协议状态、会话和健康密文是否被取走。OPAQUE 注册记录与 setup secret 一同泄露可允许离线密码猜测；恢复认证部分与完整恢复码的影响也须区别。不能仅凭“用了 AES / OPAQUE”结束调查。

## 判断范围与通知时钟

负责人尽快联系具备相关经验的律师、必要的取证人员及 Heroku 支持，逐项记录适用性、证据、结论和复查时间。免费、开源、学生项目或不适用 HIPAA 均不是通用豁免。CMIA、加州泄露法、FTC HBNR、其他受影响居民所在地法律及合同可能并行；**使用每项适用规则的期限，不能统一等 60 天**。

| 规则与条件 | 需记录和执行的期限 |
| --- | --- |
| 加州 Civil Code §1798.82，符合主体、资料及未授权取得条件 | 现行一般期限为发现或接到通知后 **30 个日历日**；只按法定执法、确定范围及恢复完整性条件延迟并留档。单次需通知 **超过 500 名加州居民**，消费者通知后 **15 个日历日**内向 AG 提交不含个人资料的样本。受托维护而非拥有资料的情形，另有立即通知所有者的义务。[现行法条](https://leginfo.legislature.ca.gov/faces/codes_displaySection.xhtml?lawCode=CIV&sectionNum=1798.82.) |
| FTC HBNR，属于覆盖的 PHR 主体且发生 unsecured PHR identifiable health information breach | 通知个人不得不合理延迟，通常最迟发现后 **60 个日历日**。涉及至少 500 人时同时报告 FTC；少于 500 人的 FTC 年度报告须在事件所在年度结束后 **60 个日历日**内，**不是次年 1 月 1 日前**。特定州/地区至少 500 名居民另有媒体通知。[FTC 指南](https://www.ftc.gov/business-guidance/resources/complying-ftcs-health-breach-notification-rule-0) |

分别统计总人数、加州人数与各州/地区人数；不要把 CA “超过 500” 与 FTC “至少 500” 混为一谈。调查未经授权披露、越权读取、浏览器明文、用户名/密码组合及第三方收到的连接数据；不能把健康网站访问元数据一律称为无敏感性。加密是否满足相应的安全港须结合实际算法、实现和密钥暴露判断。[HHS 指定加密与销毁方法](https://www.hhs.gov/hipaa/for-professionals/breach-notification/guidance/index.html)

## 通知渠道与内容

本服务不收集账号邮箱/邮址，**当前没有经过验证的批量直接联系机制或免付费号码**。这属于运营准备缺口，不免除义务。发生事件后立即由负责人落实各适用法律允许的直接或替代通知方式；不能只改 README、发 GitHub issue 或等待用户再登录。网站重要公告能辅助通知，不能当然替代法定送达。

FTC 替代通知适用时，10 人以上联系资料不足且合理联系失败，需按规则提供 90 天主页公告或相应媒体通知，并配备至少 90 天免付费电话；加州替代通知条件和组合另行核对。[16 CFR §318.5](https://www.ecfr.gov/current/title-16/chapter-I/subchapter-C/part-318/section-318.5)、[加州 AG 泄露报告入口](https://oag.ca.gov/privacy/databreach/report-a-breach)

通知须准确描述已知情况、涉事日期/发现日期、信息类型、保护措施、用户可采取的行动及联系方法。依适用法律使用规定标题/栏目、渠道和其他要素；不公开受影响名单，不在通知中索取密码，不把“调查中”写成“没有泄露”。保留通知版本、送达记录、监管提交回执和后续更正。

## 恢复与复盘

- 先确认受损版本、访问入口和秘密已处理，再恢复服务；在隔离的测试环境验证修复和跨账户隔离，不对用户记录做试验。
- Change password 重包同一数据密钥，不能用它代替数据密钥轮换。Replace recovery key / 恢复操作才为当前及后续快照换新数据密钥与恢复码。旧密文/旧包装若已被复制，不会因轮换或删除而消失。指导用户保护新恢复码并停用旧码，避免作出追溯擦除承诺。保存确认只是用户自我确认，不能保证恢复文件存在。
- OPAQUE setup 是必须持续保存的服务器认证秘密，不是健康记录解密密钥。正常重启不得重新生成；疑似泄露后的处理须设计并验证完整凭证响应，不可擅自替换后假定用户仍能登录。
- 如需恢复平台备份，先核对备份时间、OPAQUE setup 与账号记录的一致性、影响范围、用户后续更正/删除、认证版本和会话撤销记录；避免把已删除账户、旧恢复凭证、已撤销会话或待完成旧认证重新开放。恢复生产数据是需专门授权和验证的操作，本文件不执行。
- 完成事件复盘：根因、影响、通知依据、修复、待办负责人和期限。对外只说明验证过的事实。为下一次事件落实合理的监测、最小日志留存和恢复演练，再更新政策中相应承诺。

平台能力与当前配置须分开，见 [Heroku 留存核对](./heroku-retention-review-2026-09-13.md)。本流程不是律师意见、合规保证或安全认证。
